## 💡 הבעיה העסקית

גיוס כוח אדם למשטרה הוא בעיה **מרחבית**, לא רק מספרית. למנהל גיוס ארצי יש שתי שאלות פתוחות בו-זמנית:

1. **היכן הפער החמור ביותר?** אילו תחנות נמצאות מתחת לסף האיוש, וכמה תקנים חסרים בכל אחת?
2. **מאיפה לגייס?** אילו יישובים נמצאים במרחק נסיעה סביר מהתחנות החסרות — כלומר לאן להפנות תקציב פרסום ולתכנן ימי גיוס?

מערכת אקסל שטוחה עונה על השאלה הראשונה בלבד. המערכת הזו מחברת את שתיהן: היא צובעת כל תחנה
לפי חומרת הפער ומצליבה אותה מול היישובים שבטווח, כדי שההחלטה "לאן לשלוח מגייס" תתקבל על מפה
ולא על טבלה.

| מסך | מה הוא עושה |
|------|-------------|
| **מפת גיוס** | מפת חום אינטראקטיבית (Leaflet). כל תחנה נצבעת לפי אחוז איוש; לחיצה חושפת את היישובים שבטווח 30 דק'. שני מצבים: "מפת חום תחנות" ו"מפת חום יישובים" (הצד השני של אותו קשר). |
| **לוח בקרה** | KPI ראשיים: אחוז איוש משוקלל, תקן מול מאויש, פער כוח אדם ומגמת חודש, ו-Top-5 התחנות הקריטיות. |
| **ממשק מגייס** | עץ היררכי מחוז → מרחב → תחנה, עם המדדים הארציים ופירוט חוסרים לכל תחנה. |
| **תכנון אסטרטגי** | דירוג תחנות לפי **ציון דחיפות שקוף**, מפת יעדי פרסום, וניהול ימי גיוס מתוכננים. |
| **ניהול · טעינה · הגדרות** | CRUD לקשרים, טעינת אקסלים עם Data Guard, וספי צבע/מרחק הניתנים לכוונון. |

> בגרסת ההדגמה הסטטית הזו הצפייה מלאה בכל המסכים. פעולות הכתיבה (טעינת אקסל, עריכה, ייצוא לאקסל)
> קיימות בגרסת השרת המלאה ומסומנות כמושבתות כאן.

## 🧠 החלטות טכניות

מה שמעניין בפרויקט הוא לא שהקוד רץ, אלא **למה הוא בנוי כך**. שלוש החלטות מרכזיות:

### 1. טבלת קשרים במקום חישוב מרחק גאוגרפי
"יישוב קרוב לתחנה" מוגדר לפי **זמן נסיעה בפועל**, לא מרחק אווירי. שתי נקודות במרחק 3 ק"מ יכולות
להיות 8 דקות או 25 דקות זו מזו, תלוי בכבישים ובעומס. לכן הקשרים יושבים בטבלה מפורשת
(`station_settlement` עם עמודת `travel_min`), והסינון "עד 30 דק'" הוא שאילתה ישירה על העמודה —
`WHERE travel_min <= 30` — ולא חישוב `haversine` בזמן ריצה. היתרונות: הנתון ניתן לתיקון ידני
כשמסלול מסוים חריג, הוא מקור אמת יחיד לכל המסכים, והוא לא תלוי בשירות ניתוב חיצוני בזמן צפייה.

### 2. Data Guard — שכבת הגנה על טעינות
טעינת אקסל שגוי יכולה למחוק חודשי עבודה בלחיצה. **Data Guard** דוחה כל קובץ שסוטה ביותר מ-10%
מהנתונים הקיימים (למשל קובץ שמכיל 12 תחנות במקום 88 — כנראה קובץ חלקי או שגוי), ולפני כל טעינה
מוצלחת נשמר גיבוי אוטומטי. זו אינה זהירות יתר: מסך הניהול מאפשר מחיקה בלחיצה ואין "בטל" — הגיבוי
הוא הדרך היחידה לחזור.

### 3. "מצב ריק מפורש" — לעולם לא אפס במקום חוסר נתון
כלל הברזל של המערכת: **היכן שאין נתון — מוצג "אין נתונים", לעולם לא 0**. אפס מועמדים ("אף אחד לא
בהליך") הוא מסקנה שונה לגמרי מ"לא נטען קובץ מועמדים". לכן שדה "מועמדים בהליך" מוצג כ"אין נתון" בחלק
מהתחנות ולא כאפס — גם בהדגמה הזו. החלטה עסקית שגויה על בסיס אפס מזויף גרועה מהחלטה מדחיית תשובה.

### 4. שיוך מקצועות לארבע משפחות לפי כלל תת-מחרוזת
קובץ המקור מפרט עשרות מקצועות פרטניים ("חוקר/מד"ר", "חוקרת נוער חרדית", "בילוש", "בלש חרדי",
"סייר/מגילות"), ומדי פעם צצים מקצועות חדשים שאינם משויכים מראש. במקום לתחזק רשימה סגורה, השיוך
נעשה לפי **תת-מחרוזת** לאחת מארבע משפחות: מקצוע שמכיל *חוקר/חקירות* → **חוקר** (כך גם "חוקרת נוער"
נופל למקומו), *סייר/סיור* → **סייר**, *בלש/בילוש* → **בלש**, וכל השאר → **אחר**. זה מה שמאפשר
לתפוס מקצוע חדש בלי לגעת בקוד.

### עקרונות משלימים
- **מקור אמת יחיד לצבעים:** בגרסת השרת הסטטוס והצבע מחושבים בשרת (`ingest/colors.py`) ונשלחים
  ללקוח מוכנים — כדי שהמפה, המקרא, הטבלאות והייצוא לא יוכלו לסטות זה מזה. בהדגמה הסטטית אותה
  לוגיקה משוכפלת במחולל הנתונים, כך שהצבעים זהים לחלוטין.
- **ציון דחיפות שקוף:** `(100 − אחוז איוש) × מקדם_קריטיות × (1 + תקנים_חסרים/10)`. הנוסחה והמקדמים
  ניתנים לכוונון בהגדרות, כי מנהל שמקצה תקציב לפי ציון חייב לדעת איך הוא התקבל.

## 🏗️ ארכיטקטורה

<div dir="ltr">

```
┌─────────────── גרסת השרת המלאה ───────────────┐        ┌──── גרסת הפורטפוליו (כאן) ────┐
                                                          
  Excel ──► ingest/ (pandas + Data Guard)                  tools/generate_demo_data.py
              │  נרמול · ולידציה · גיבוי                       │  (מגריל נתונים סינתטיים)
              ▼                                               ▼
          SQLite (db/heatmap.db)                          data/*.json  (סטטי, קפוא)
              │                                               │
          Flask API  /api/*  (app.py)                     GitHub Pages (ללא שרת)
              │                                               │
              ▼                                               ▼
     Leaflet + Vanilla JS (web/) ◄───── אותו app.js ─────► Leaflet + Vanilla JS
```

</div>

**למה סטטי לפורטפוליו?** מפת החום היא קריאה-בלבד: היא מציגה נתונים, לא כותבת אליהם. לכן אפשר לוותר
על Flask לגמרי — לייצא את הטבלאות מ-SQLite לקובצי JSON ולתת ל-JavaScript לקרוא אותם ישירות. `app.js`
זהה למקור; רק פונקציית `api()` הוחלפה כך שתתרגם כל נתיב `/api/*` לקובץ `data/*.json`. התוצאה: קישור
שעובד מיידית וללא cold start, חינם, ומגייס שלוחץ רואה מפה תוך שנייה.

## 🛠️ מחסנית טכנולוגית

- **Frontend:** Vanilla JavaScript (ללא framework), Leaflet.js למפה, CSS מותאם (RTL, עברית מלאה)
- **Backend (גרסה מלאה):** Python · Flask · SQLite
- **עיבוד נתונים:** pandas · שכבת נרמול ושידוך שמות · Data Guard
- **הדגמה:** ייצוא סטטי ל-JSON · GitHub Pages · **אפס תלויות ריצה בצד לקוח**
